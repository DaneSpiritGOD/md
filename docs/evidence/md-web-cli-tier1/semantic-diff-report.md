## Explained differences

- **class and auto heading-id attributes** — The Oracle is the browser copy-flow output and keeps class="..." / id="N" attributes; the CLI strips them by design for WeChat (copy flow strips classes after juice). All such hunks are accepted.
- **inline body color on the container** — The CLI writes color: rgb(10,10,10) inline on the root section; the Oracle inherits the same value from the page body element (it never becomes an inline declaration). Decision recorded in the ticket: body text color settles at rgb(10,10,10) to match the browser baseline.
- **table margin-top reset** — The Oracle table carries margin-top: 0 !important (paste-side reset in the browser flow); the CLI omits it. Visual impact is nil because the preceding heading already sets margin-bottom.
- **SVG width/height unit suffix** — Mac code-block dots SVG: Oracle has width="45" height="13"; CLI emits width="45px" height="13px". Equivalent rendering in Chromium/WeChat.
- **link href trailing slash** — The browser copy flow normalizes https://example.com to https://example.com/ via URL parsing; the CLI keeps the Markdown-authored form. Same target.
- **mac-sign SVG overflow attribute** — The Oracle mac-sign SVG carries overflow="visible" (the default, emitted explicitly by the browser copy flow); the CLI omits it. Same rendered result.
- **container color presence** — The CLI writes color: rgb(10,10,10) inline on the root section; the Oracle has no inline color because the value is inherited from the page body element of the editor page. In a plain rendering context (no editor CSS) the Oracle section computes rgb(0,0,0) while the CLI computes rgb(10,10,10) — verified headlessly with computed styles; the delta is imperceptible (all channels 10/255). Ticket 07 decision: body text color settles at rgb(10,10,10) to match the editor’s browser baseline, which is what WeChat readers effectively see in the copy flow.
- **Oracle HTML comment header** — The Oracle file starts with a provenance comment; the CLI output has none.
